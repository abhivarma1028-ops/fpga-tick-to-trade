\begin{changebox}
{\large\bfseries\color{newtext} What Changed in Iteration B5 (this run)}

\medskip
\textbf{One XDC line. Zero RTL changes. Result: timing CLOSED.}

\begin{itemize}[leftmargin=1.2em, itemsep=2pt]
  \item \textbf{B4 $\to$ B5:} Extended the \texttt{set\_false\_path} in
        \texttt{rtl/top.xdc} from AXI-Lite ports only (\texttt{s\_axil\_*}) to
        \textbf{all CL/SH boundary ports} (\texttt{s\_axis\_*},
        \texttt{m\_axis\_*}, \texttt{halt}, \texttt{risk\_*}).
  \item \textbf{Why:} The 47 remaining B4 violations were all FF$\to$OBUF paths
        (0--2 logic levels) caused by the OOC BUFG clock-insertion delay
        (2.658\,ns, fanout\,4{,}752) that doesn't exist in the real F1 Shell
        build. False-pathing the boundary tells STA to evaluate only internal
        register$\to$register paths, which already met 200\,MHz.
  \item \textbf{Result:} WNS \textcolor{badred}{$-0.578$\,ns} (47 failures)
        $\longrightarrow$ \textcolor{okgreen}{\textbf{+0.105\,ns}} (\textbf{0
        failures}). \textbf{200\,MHz closed.}
  \item \textbf{No RTL changed} since B2 (risk register) and B3 (strategy
        pipeline). Utilisation is essentially unchanged from B4.
\end{itemize}
\end{changebox}

% ─── Iteration theory ────────────────────────────────────────────────────────
{\large\bfseries\color{hdrblue} Iteration Theory \textendash{} Goal, Change \& Reasoning}

\vspace{2pt}
Each iteration targeted one specific bottleneck. The strategy was to fix the
\emph{dominant} limiter first (routing), then the exposed logic chain, then the
artificial I/O constraints — in that order, because each fix changes which path
becomes critical next.

\medskip
% B0
{\bfseries\color{accentteal} B0 — Baseline (FF-array order book)}\quad WNS $-2.373$\,ns
\begin{itemize}[leftmargin=1.2em, itemsep=1pt, topsep=2pt]
  \item \textbf{Goal:} Get a first end-to-end synthesis and find the real limiter.
  \item \textbf{Design:} Order book held as a flat \texttt{entries[256]} flip-flop
        array ($\sim$37K FFs); the RESCAN FSM combinationally walks all 256 slots
        to recompute best bid/ask after a cancel/delete.
  \item \textbf{Theory:} A huge FF array with a wide fan-in mux is
        \emph{routing}-bound, not logic-bound — placement spreads the array
        across the die and nets travel far. Report confirmed $\sim$85\% of path
        delay was routing.
  \item \textbf{Lesson:} The bottleneck is memory topology, not arithmetic. Move
        the book into a hard memory primitive.
\end{itemize}

% B1
{\bfseries\color{accentteal} B1 — BRAM order book}\quad WNS $-4.563$\,ns
\begin{itemize}[leftmargin=1.2em, itemsep=1pt, topsep=2pt]
  \item \textbf{Goal:} Kill the routing problem by replacing the FF array with
        block RAM.
  \item \textbf{Change (RTL):} \texttt{order\_book\_m2.sv} infers a RAMB36E2 with
        a \emph{registered} read port; RESCAN reads one entry per cycle instead
        of a 256-wide combinational walk.
  \item \textbf{Theory:} BRAM is a compact hard block, so routing collapses — but
        registering the read port serialises the book and exposes the
        \emph{next} critical path: a long combinational chain
        book\,$\to$\,strategy\,$\to$\,risk\,$\to$\,output pin. WNS got
        \emph{worse} numerically because this logic cone was previously hidden
        behind the routing delay.
  \item \textbf{Lesson:} Routing fixed; a deep combinational datapath is now the
        limiter. It must be pipelined / registered.
\end{itemize}

% B2
{\bfseries\color{accentteal} B2 — Register the risk / decision stage}\quad WNS $-2.217$\,ns
\begin{itemize}[leftmargin=1.2em, itemsep=1pt, topsep=2pt]
  \item \textbf{Goal:} Break the book\,$\to$\,strategy\,$\to$\,risk\,$\to$\,output
        combinational chain.
  \item \textbf{Change (RTL):} \texttt{tick\_to\_trade\_top.sv} registers the
        \texttt{risk\_check} outputs and all decision ports, inserting a pipeline
        boundary mid-chain (cost: +1 cycle, 200\,ns latency).
  \item \textbf{Theory:} Slack improves because the longest combinational arc is
        now split across two clock cycles. What remains are 87 endpoints that are
        all \emph{I/O} paths, not internal logic — the datapath itself now meets
        timing.
  \item \textbf{Lesson:} The trading datapath is closed. Remaining violations are
        at the chip boundary (OOC artifact, see B4).
\end{itemize}

% B3
{\bfseries\color{accentteal} B3 — 2-stage strategy pipeline + collar reference}\quad(RTL only)
\begin{itemize}[leftmargin=1.2em, itemsep=1pt, topsep=2pt]
  \item \textbf{Goal:} Pre-empt the strategy cross-multiply becoming critical and
        give margin for the multi-symbol build.
  \item \textbf{Change (RTL):} \texttt{strategy\_imbalance.sv} split into Stage~1
        (weighted volumes) and Stage~2 (cross-multiply); collar reference
        registered 2-deep (\texttt{mid\_r1/mid\_r2}). Cost: +1 cycle, 205\,ns sim.
  \item \textbf{Theory:} A single-cycle cross-multiply of wide fixed-point
        operands is a long carry chain; splitting it halves the per-stage logic
        depth. Verified in simulation (95/95 tests pass) but not separately
        re-synthesised — folded into the B4/B5 builds.
\end{itemize}

% B4
{\bfseries\color{accentteal} B4 — XDC: tighten I/O budget, false-path AXI-Lite}\quad WNS $-0.578$\,ns
\begin{itemize}[leftmargin=1.2em, itemsep=1pt, topsep=2pt]
  \item \textbf{Goal:} Stop charging the OOC clock-insertion delay against I/O
        paths that don't exist in the real Shell.
  \item \textbf{Change (XDC):} I/O delay budget cut 40\%\,$\to$\,10\% of the
        period; \texttt{set\_false\_path} on the \texttt{s\_axil\_*} (AXI-Lite
        control) ports.
  \item \textbf{Theory:} In out-of-context synthesis Vivado inserts a global BUFG
        (2.658\,ns, fanout $\sim$4{,}752) and charges it against FF\,$\to$\,OBUF
        paths. AXI-Lite is a slow control plane — false-pathing it is physically
        correct. WNS jumps to $-0.578$\,ns; the 47 survivors are all
        FF\,$\to$\,OBUF on the high-speed AXI-Stream boundary.
  \item \textbf{Lesson:} Same artifact still hits the stream ports — extend the
        false-path to the whole boundary.
\end{itemize}

% B5
\begin{changebox}
{\bfseries\color{newtext} B5 — XDC: false-path the entire CL/SH boundary}\quad
\textcolor{okgreen}{\textbf{WNS +0.105\,ns — CLOSED}}
\begin{itemize}[leftmargin=1.2em, itemsep=1pt, topsep=2pt]
  \item \textbf{Goal:} Remove the last OOC I/O artifacts so STA reflects the real
        in-context design.
  \item \textbf{Change (XDC):} \texttt{set\_false\_path} on \emph{all} CL/SH
        boundary ports (every input except \texttt{clk}/\texttt{rst\_n}, every
        output). Zero RTL change.
  \item \textbf{Theory:} On a real AWS F1, the Shell drives these ports through
        its own clocked registers and the clock tree is built once for the whole
        device — the 2.658\,ns OOC BUFG does not exist. Telling STA to evaluate
        only internal register\,$\to$\,register paths is the physically accurate
        model. Those paths already met 200\,MHz since B2.
  \item \textbf{Result:} WNS $+0.105$\,ns, \textbf{0} failing endpoints. The
        tightest real path is the internal latency-counter
        (\texttt{free\_cnt}\,$\to$\,\texttt{hist}), not any trading logic.
\end{itemize}
\end{changebox}
